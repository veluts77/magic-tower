# Coding Agent Rules

Эти правила обязательны для исполнительного агента.

---

## 1. Technology Stack

Используем только:

- Java 21
- Gradle
- libGDX
- Desktop LWJGL3 backend

Запрещено без явного разрешения:

- менять язык на Kotlin, Groovy, Scala;
- менять libGDX на другой фреймворк;
- добавлять новые внешние зависимости;
- добавлять мобильные или веб-таргеты;
- добавлять серверную часть.

---

## 2. Scope Discipline

Выполняй только текущую задачу.

Не добавляй:

- геймплей, если задача не про геймплей;
- UI, если задача не про UI;
- данные, если задача не про данные;
- анимации, если они не нужны;
- будущие системы заранее.

Если кажется, что нужно сделать что-то заранее:
- не делай;
- напиши это в отчёте как предложение.

---

## 3. Code Style

Используй простой, читаемый Java-код.

Рекомендации:

- пакеты начинаются с `tower.`;
- имена классов на английском;
- комментарии могут быть краткими;
- не использовать Lombok;
- не использовать reflection без необходимости;
- не создавать сложные абстракции заранее;
- предпочитать композицию и простые классы.

---

## 4. Architecture

Соблюдай принципы из `ARCHITECTURE.md`.

Особенно важно:

- игровая логика не должна зависеть от конкретного UI;
- данные не должны быть зашиты в код, если это уже этап данных;
- рендеринг должен быть отделён от состояния;
- не делать глобальные mutable singletons без необходимости.

---

## 5. Assets

На текущем этапе:

- не генерировать бинарные ассеты;
- не скачивать картинки;
- не создавать сложные спрайты;
- использовать placeholder-графику только если задача этого требует.

Папка `assets` должна существовать.

---

## 6. Verification

Предпочтительная проверка:

```bash
./gradlew build
```

Если задача требует запуска:

```bash
./gradlew desktop:run
```

Но пользователь часто будет собирать и проверять самостоятельно.
Поэтому агенту не нужно многократно запускать GUI без необходимости.

Если агент работает в среде без GUI:

- проверь хотя бы `./gradlew build`;
- в отчёте напиши: `GUI not tested`.

---

## 7. Error Reporting

Если что-то не работает:

- не вставляй весь многостраничный лог;
- покажи только релевантную часть ошибки;
- укажи команду, которая завершилась с ошибкой;
- укажи, что уже пробовал.

---

## 8. Updating State

После выполнения задачи агент должен обновить `STATE.md`.

Обновление должно быть коротким:

- что выполнено;
- что сейчас в работе;
- какая задача следующая;
- есть ли блокеры.

---

## 9. Safety

Не удаляй:

- документацию;
- задачи;
- существующие исходники без необходимости;
- файлы состояния.

Если файл нужно перезаписать:

- убедись, что это требуется задачей;
- упомяни это в отчёте.

---

## 10. Token Economy

Отчёты должны быть краткими.

Не нужно:

- пересказывать всю документацию;
- вставлять весь код без необходимости;
- вставлять огромные логи;
- подробно объяснять очевидные вещи.

Нужно:

- что сделано;
- что проверено;
- какие файлы изменены;
- какие проблемы возникли.
