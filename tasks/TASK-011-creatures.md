# TASK-011 — Creatures and Creature Interaction

## Goal

Добавить в игру систему существ — пассивных обитателей башни, которые
могут блокировать доступ к объектам или переходам, и с которыми можно
взаимодействовать через заклинания.

Существа работают как особый тип объектов в комнате с дополнительными
свойствами: они могут быть нейтрализованы определёнными заклинаниями.

## Design Context

В TASK-007, TASK-008 и TASK-009 мы реализовали взаимодействие с объектами,
заклинаниями и духами. Существа — это следующий тип сущностей в мире игры.

Ключевые особенности:

- Существо находится в комнате как объект.
- Существо может блокировать доступ к другим объектам или переходам.
- Существо можно осмотреть (получить описание).
- Существо можно нейтрализовать определённым заклинанием.
- После нейтрализации существо не блокирует доступ.
- Попытка взаимодействия без нейтрализации может быть неудачной.

Пример:
- В комнате есть существо "пепельный слизень".
- За существом находится объект "сундук".
- Игрок пытается осмотреть сундук, но слизень блокирует доступ.
- Игрок применяет заклинание `spark` к слизню.
- Слизень нейтрализуется (исчезает или уходит).
- Теперь сундук доступен для взаимодействия.

Это демонстрирует, что существа интегрируются в существующую модель
действий, но имеют особые правила взаимодействия.

## Scope

Входит в задачу:

1. Модель существа в `domain`:
    - идентификатор (строка);
    - отображаемое имя;
    - описание;
    - список заклинаний, которые могут нейтрализовать существо
      (например, `spark`).

2. Загрузка существ из JSON:
    - создать структуру `assets/data/creatures/`;
    - создать тестовый JSON с описанием одного существа
      `ash_slug` (пепельный слизень), который нейтрализуется заклинанием `spark`;
    - расширить `DataLoader` для загрузки существ.

3. Расширение определения объекта в `domain`:
    - добавить поле `существо` (идентификатор существа, если объект
      является существом; иначе null).

4. Состояние комнаты в `domain`:
    - добавить поле для отслеживания нейтрализованных существ
      (список идентификаторов нейтрализованных существ в комнате).

5. Расширение определения объекта в `domain`:
    - добавить поле `блокируется существом` (идентификатор существа,
      которое блокирует доступ к этому объекту; иначе null).

6. Расширение резолвера действий в `domain`:
    - при получении действий для объекта:
        * если объект заблокирован существом и существо не нейтрализовано,
          большинство действий недоступны (кроме осмотра);
        * если объект является существом, добавить действия:
            - осмотреть существо;
            - применить заклинание (если у игрока есть заклинание, которое
              нейтрализует это существо, и существо ещё не нейтрализовано).

7. Расширение экзекутора действий в `domain`:
    - поддержать действие `применить заклинание` к существу:
        * если заклинание нейтрализует существо, отметить существо
          как нейтрализованное;
        * вернуть текстовый результат (существо нейтрализовано);
    - при попытке взаимодействия с заблокированным объектом:
        * если блокирующее существо не нейтрализовано, вернуть сообщение
          о том, что доступ заблокирован;
        * не менять состояние.

8. Обновить тестовые данные:
    - в одной из комнат должно быть существо `ash_slug`;
    - в той же комнате должен быть объект, заблокированный этим существом;
    - существо должно иметь описание для осмотра;
    - существо должно поддерживать нейтрализацию заклинанием `spark`.

9. Юнит-тесты в `domain` для:
    - загрузки существа;
    - осмотра существа;
    - недоступности взаимодействия с заблокированным объектом;
    - нейтрализации существа заклинанием;
    - доступности заблокированного объекта после нейтрализации;
    - недоступности повторной нейтрализации уже нейтрализованного существа.

Не входит в задачу:

- Другие существа (только `ash_slug` для проверки архитектуры).
- Агрессивные существа, которые атакуют игрока.
- Существа, которые дают предметы после нейтрализации.
- Визуальные эффекты (анимация нейтрализации, спрайты).
- Mastery marks и прогрессия этажа.
- Сохранение и загрузка состояния.
- Сложные поведения существ (патрулирование, реакция на звуки).

## Module Placement

- Модель существа → модуль `domain`, пакет `tower.domain.data` или `tower.domain.creature`.
- Расширение состояния комнаты → модуль `domain`, пакет `tower.domain.state`.
- Расширение резолвера и экзекутора → модуль `domain`, пакет `tower.domain.logic`.
- Загрузка существ → модуль `engine`, пакет `tower.engine.data`.
- Тестовые JSON-файлы → `assets/data/creatures/`.

Перед началом изучи фактическую структуру кода после предыдущих задач.
Не предполагай имена существующих классов.
Расширяй существующую модель, а не создавай параллельную.

## Constraints

- Не добавлять новые внешние зависимости.
- У `domain` по-прежнему ноль runtime-зависимостей.
- DTO-классы должны оставаться совместимыми с существующим парсером в `engine`.
- Существо работает через существующую модель действий,
  не требует отдельной системы.
- Существа пассивные: не атакуют игрока автоматически.
- Нейтрализация существа — это действие `применить заклинание` к существу.
- Нейтрализованное существо не блокирует доступ к объектам.
- Нейтрализованное существо может остаться в комнате (видимо как объект),
  но не блокирует и не может быть нейтрализовано повторно.
- Если объект заблокирован существом, большинство действий с объектом
  недоступны до нейтрализации существа.
- Не менять `desktop`.

## Acceptance Criteria

1. В `assets/data/creatures/` существует JSON-файл с описанием существа
   `ash_slug`.
2. Существо загружается при старте игры.
3. В одной из тестовых комнат есть существо как объект.
4. В той же комнате есть объект, заблокированный этим существом.
5. При выборе существа в списке действий появляется `Осмотреть` и
   `Применить: Искра` (если игрок знает это заклинание).
6. При осмотре существа отображается его описание.
7. При попытке взаимодействия с заблокированным объектом отображается
   сообщение о том, что доступ заблокирован.
8. Применение заклинания `spark` к существу нейтрализует его.
9. После нейтрализации заблокированный объект становится доступен
   для взаимодействия.
10. Повторная нейтрализация уже нейтрализованного существа недоступна.
11. Юнит-тесты для всех сценариев существуют и проходят.
12. `./gradlew build` завершается успешно.
13. `./gradlew domain:test` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew domain:test
./gradlew desktop:run
```

При запуске:

- в комнате видны существо и заблокированный объект;
- попытка взаимодействия с заблокированным объектом не работает;
- можно применить заклинание к существу;
- существо нейтрализуется;
- заблокированный объект становится доступен.

Проверка, что модуль `desktop` не менялся:

```bash
git diff --name-only desktop/
```

Команда должна вернуть пустой результат.
