# TASK-016 — UI Layout Fix: Fixed Bottom Panel and Room Scaling

## Goal

Исправить макет игрового экрана:

- зафиксировать высоту нижней панели;
- убрать большую чёрную рамку вокруг комнаты;
- обеспечить правильное масштабирование фона комнаты на доступную область;
- обеспечить правильное масштабирование объектов.

Это подготовительный шаг перед заменой автоматической раскладки объектов
на явное позиционирование.

## Design Context

В текущей реализации нижняя панель содержит:

- информацию о прогрессе печатей;
- список доступных действий;
- сообщения о результатах действий.

При увеличении количества действий панель растёт по высоте,
а область комнаты сжимается. Это приводит к тому, что комната
становится всё меньше и меньше.

Кроме того, вокруг комнаты отображается большая чёрная рамка,
которая занимает полезное пространство.

Цель этой задачи — зафиксировать макет экрана:

- Нижняя панель всегда имеет фиксированную высоту.
- Комната занимает всё оставшееся пространство.
- Фон комнаты масштабируется на всю доступную область.
- Объекты масштабируются корректно.

## Scope

Входит в задачу:

1. Зафиксировать высоту нижней панели.
    - Высота панели: 120 пикселей.
    - Панель не должна расти при увеличении количества действий.
    - Если действий больше, чем помещается в панель,
      они должны быть видимы без прокрутки.
      На данном этапе допускается, что часть действий не отображается,
      если их слишком много. Прокрутка не требуется.

2. Комната занимает всё пространство выше нижней панели.
    - При размере окна 1280×720 область комнаты составляет 1280×600.
    - Комната должна заполнять эту область полностью.

3. Убрать большую чёрную рамку вокруг комнаты.
    - Чёрная рамка вокруг комнаты должна быть убрана или уменьшена до минимума.
    - Фон комнаты должен занимать всю доступную область без лишних отступов.

4. Оставить тонкую рамку для нижней панели.
    - Нижняя панель может иметь тонкую рамку или границу.
    - Декорирование рамки не требуется на этом этапе.

5. Обеспечить масштабирование фона комнаты на доступную область.
    - Фоны комнат имеют размер 1280×720.
    - Область комнаты имеет размер 1280×600 (720 − 120 панель).
    - Фон должен быть отмасштабирован или обрезан так,
      чтобы заполнить область комнаты без чёрных полос.
    - Рекомендуется масштабировать по ширине и обрезать по высоте,
      либо обрезать лишние пиксели по высоте.

6. Обеспечить масштабирование объектов.
    - Объекты имеют размер 128×128.
    - Объекты должны масштабироваться при отрисовке.
    - Масштабирование должно сохранять пропорции.
    - На данном этапе автоматическая раскладка объектов сохраняется.
      Явное позиционирование будет добавлено в следующей задаче.

7. Сохранить существующую функциональность.
    - Выбор объектов и действия должны работать как раньше.
    - Отображение прогресса печатей должно работать.
    - Отображение сообщений о результатах действий должно работать.
    - Переходы между комнатами должны работать.

Не входит в задачу:

- Явное позиционирование объектов (координаты, размеры, z-порядок).
- Удаление надписей к объектам.
- Разделение объектов на интерактивные и декоративные.
- Изменение механик игры.
- Изменение данных комнат.
- Изменение модуля `domain`.
- Изменение модуля `desktop`.

## Module Placement

Только модуль `engine`.

Предполагаемые области:

- макет игрового экрана → `tower.engine.screen`;
- отрисовка комнаты → `tower.engine.render`;
- отрисовка нижней панели → `tower.engine.render` или `tower.engine.ui`.

Перед началом изучи фактическую структуру кода после предыдущих задач.
Не предполагай имена существующих классов.

## Constraints

- Не добавлять новые внешние зависимости.
- Не изменять модуль `domain`.
- Не изменять модуль `desktop`.
- Не изменять автоматическую раскладку объектов.
- Не удалять надписи к объектам.
- Не менять разрешение окна (оно уже 1280×720).
- Высота нижней панели фиксирована: 120 пикселей.
- Прокрутка списка действий не требуется.
- Большая чёрная рамка вокруг комнаты должна быть убрана.
- Тонкая рамка для нижней панели допустима.
- Фон комнаты должен заполнять доступную область без чёрных полос.
- Объекты должны масштабироваться с сохранением пропорций.

## Acceptance Criteria

1. Нижняя панель имеет фиксированную высоту 120 пикселей.
2. Нижняя панель не растёт при увеличении количества действий.
3. Комната занимает всё пространство выше нижней панели.
4. Большая чёрная рамка вокруг комнаты убрана.
5. Нижняя панель имеет тонкую рамку или границу.
6. Фон комнаты заполняет доступную область без чёрных полос.
7. Объекты масштабируются с сохранением пропорций.
8. Выбор объектов и действия работают как раньше.
9. Отображение прогресса печатей работает.
10. Переходы между комнатами работают.
11. Модуль `domain` не изменён.
12. Модуль `desktop` не изменён.
13. `./gradlew build` завершается успешно.
14. `./gradlew domain:test` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew domain:test
./gradlew desktop:run
```

При запуске:

- окно имеет размер 1280×720;
- комната занимает верхнюю часть окна (1280×600);
- нижняя панель занимает нижнюю часть окна (1280×120);
- фон комнаты заполняет доступную область;
- большая чёрная рамка вокруг комнаты отсутствует;
- нижняя панель имеет тонкую рамку;
- объекты отображаются и масштабируются корректно;
- выбор объектов и действия работают.

Проверка, что домен и запускатор не менялись:

```bash
git diff --name-only domain/ desktop/
```

Команда должна вернуть пустой результат.

Если GUI недоступен, достаточно успешной сборки и тестов,
а в отчёте указать: `GUI not tested`.
