# TASK-012 — Mastery Marks and Floor Progression

## Goal

Добавить в игру систему печатей понимания (mastery marks) и прогрессии
этажа. Игрок получает печати за выполнение определённых действий в комнатах
этажа. Когда собрано достаточно печатей (примерно 80%), открывается
возможность подняться на следующий этаж.

Это превращает исследование в прогрессию и даёт игроку цель.

## Design Context

В предыдущих задачах мы реализовали несколько механик:
- навигация между комнатами (TASK-006);
- взаимодействие с объектами (TASK-007);
- заклинания (TASK-008);
- духи (TASK-009);
- артефакты (TASK-010);
- существа (TASK-011).

Теперь нужно связать эти механики в единую систему прогрессии.

Ключевые особенности:

- Каждый этаж имеет набор печатей понимания (например, 8 печатей).
- Печать выдаётся за выполнение определённого действия
  (например, подбор артефакта, нейтрализация существа, призыв духа).
- Игрок видит, сколько печатей собрано и сколько нужно для прогресса.
- Когда собрано достаточно печатей (например, 7 из 8), открывается
  действие "подняться выше".
- Переход на следующий этаж переводит игрока на новый этаж.

Пример:
- Этаж имеет 8 печатей.
- Печать 1: найти заклинание `spark`.
- Печать 2: подобрать артефакт `ring_of_quiet_flame`.
- Печать 3: нейтрализовать существо `ash_slug`.
- Печать 4: призвать духа `seeker` в комнате `зал_карт`.
- Печать 5: осмотреть объект `древний_фолиант`.
- Печать 6: перейти в комнату `скрытая_келья`.
- Печать 7: применить заклинание `spark` к объекту `факел`.
- Печать 8: решить загадку (упрощённо: применить заклинание к определённому объекту).
- Нужно собрать 7 из 8 печатей для подъёма.

Это демонстрирует, что система прогрессии интегрируется с существующими
механиками и не требует их переписывания.

## Scope

Входит в задачу:

1. Модель печати понимания в `domain`:
    - идентификатор (строка);
    - отображаемое имя;
    - описание;
    - условие получения: тип действия и идентификатор цели
      (например, `pick_artifact` + `ring_of_quiet_flame`).

2. Модель этажа в `domain`:
    - список печатей понимания;
    - порог для перехода (например, 7 из 8);
    - метод проверки, достаточно ли печатей для перехода.

3. Состояние этажа в `domain`:
    - список полученных печатей;
    - метод добавления печати;
    - метод проверки, получена ли печать;
    - метод получения количества полученных печатей.

4. Загрузка печатей из JSON:
    - расширить определение этажа полем `печати`;
    - обновить тестовый JSON этажа с описанием 8 печатей;
    - расширить `DataLoader` для загрузки печатей.

5. Система выдачи печатей в `domain`:
    - после выполнения действия экзекутор проверяет, должна ли быть
      выдана печать;
    - если условие печати совпадает с выполненным действием, печать добавляется;
    - проверка происходит в экзекуторе или в отдельном сервисе прогрессии.

6. Переход на следующий этаж:
    - расширить резолвер действий для комнаты:
        * если в комнате есть переход на следующий этаж и печатей достаточно,
          добавить действие `подняться выше`;
        * если печатей недостаточно, действие не появляется;
    - расширить экзекутор:
        * при выполнении действия `подняться выше` перевести игрока
          на следующий этаж;
        * сбросить состояние предыдущего этажа (посещённые комнаты,
          состояние объектов);
        * вернуть текстовый результат.

7. Отображение прогресса:
    - расширить игровой экран в `engine`:
        * показывать количество собранных печатей и порог для перехода
          (например, "Печати: 5/8, нужно 7");
        * показывать сообщение о получении новой печати;
        * показывать сообщение о том, что путь наверх открыт.

8. Обновить тестовые данные:
    - тестовый этаж должен иметь 8 печатей;
    - каждая печать привязана к конкретному действию и цели;
    - порог для перехода — 7 из 8;
    - в этаже должен быть переход на следующий этаж
      (даже если следующий этаж пока пустой или минимальный).

9. Юнит-тесты в `domain` для:
    - загрузки печатей;
    - выдачи печати при выполнении соответствующего действия;
    - недоступности повторной выдачи уже полученной печати;
    - проверки количества собранных печатей;
    - недоступности перехода при недостатке печатей;
    - доступности перехода при достаточном количестве печатей;
    - перехода на следующий этаж и сброса состояния.

Не входит в задачу:

- Полноценный второй этаж (достаточно минимального или пустого).
- Визуальные эффекты печатей (иконки, спрайты).
- Сохранение и загрузка прогресса между этажами.
- Сложные условия печатей (комбинации действий, временные условия).
- Анимация перехода между этажами.

## Module Placement

- Модель печати и этажа → модуль `domain`, пакет `tower.domain.data`.
- Состояние этажа → модуль `domain`, пакет `tower.domain.state`.
- Система выдачи печатей → модуль `domain`, пакет `tower.domain.logic`.
- Расширение резолвера и экзекутора → модуль `domain`, пакет `tower.domain.logic`.
- Загрузка печатей → модуль `engine`, пакет `tower.engine.data`.
- Отображение прогресса → модуль `engine`, пакет `tower.engine.screen`.

Не предполагай имена существующих классов.
Расширяй существующую модель, а не создавай параллельную.

## Constraints

- Не добавлять новые внешние зависимости.
- У `domain` по-прежнему ноль runtime-зависимостей.
- DTO-классы должны оставаться совместимыми с существующим парсером в `engine`.
- Система печатей работает через существующую модель действий,
  не требует отдельной системы.
- Печать выдаётся только один раз за действие.
- Переход на следующий этаж доступен только при достаточном количестве печатей.
- При переходе на следующий этаж состояние предыдущего этажа сбрасывается.
- Не менять `desktop`.

## Acceptance Criteria

1. Тестовый этаж содержит 8 печатей в JSON.
2. Печати загружаются при старте игры.
3. При выполнении соответствующего действия печать выдаётся.
4. Отображается сообщение о получении новой печати.
5. Повторная выдача уже полученной печати не происходит.
6. Отображается прогресс печатей (например, "Печати: 5/8, нужно 7").
7. При недостатке печатей действие "подняться выше" недоступно.
8. При достаточном количестве печатей действие "подняться выше" появляется.
9. Переход на следующий этаж работает (даже если следующий этаж минимальный).
10. После перехода состояние предыдущего этажа сбрасывается.
11. Юнит-тесты для всех сценариев существуют и проходят.
12. `./gradlew build` завершается успешно.
13. `./gradlew domain:test` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew domain:test
./gradlew desktop:run
```

При запуске:

- виден прогресс печатей;
- при выполнении действий печати выдаются;
- при достаточном количестве печатей появляется действие "подняться выше";
- переход на следующий этаж работает.
