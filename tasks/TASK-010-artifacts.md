# TASK-010 — Artifacts and Passive Effects

## Goal

Добавить в игру систему артефактов — магических предметов, которые игрок
может найти и экипировать, получая пассивные эффекты.

Артефакты работают как особый тип объектов в комнате, которые можно
подобрать. После подбора они занимают один из слотов экипировки и
автоматически применяют свой эффект.

## Design Context

В TASK-008 и TASK-009 мы реализовали активные магические механики
(заклинания и духи). Артефакты — это пассивная магическая система.

Ключевые особенности:

- Артефакт находится в комнате как объект.
- Игрок может подобрать артефакт (действие "подобрать").
- Артефакт занимает один из ограниченных слотов экипировки.
- Эффект артефакта применяется автоматически при определённых условиях.
- Пример: "Кольцо тихого пламени" защищает от огненного урона
  или позволяет пройти через огненную завесу.

Это демонстрирует, что система действий поддерживает разные типы
взаимодействий: активные (заклинания, духи) и пассивные (артефакты).

## Scope

Входит в задачу:

1. Модель артефакта в `domain`:
    - идентификатор (строка);
    - отображаемое имя;
    - описание;
    - тип эффекта (например, `fire_protection`).

2. Состояние игрока в `domain`:
    - список слотов экипировки (например, 3 слота);
    - метод экипировки артефакта в свободный слот;
    - метод проверки, экипирован ли артефакт;
    - метод получения эффекта артефакта (если экипирован).

3. Загрузка артефактов из JSON:
    - создать структуру `assets/data/artifacts/`;
    - создать тестовый JSON с описанием одного артефакта
      `ring_of_quiet_flame` (кольцо тихого пламени) с эффектом `fire_protection`;
    - расширить `DataLoader` для загрузки артефактов.

4. Расширение определения объекта в `domain`:
    - добавить поле `артефакт` (идентификатор артефакта, если объект
      является артефактом; иначе null).

5. Расширение резолвера действий в `domain`:
    - при получении действий для объекта, если объект является артефактом
      и ещё не подобран, добавить действие `подобрать артефакт`;
    - действие должно иметь тип `подобрать артефакт` и цель `идентификатор объекта`.

6. Расширение экзекутора действий в `domain`:
    - поддержать действие `подобрать артефакт`;
    - при подборе артефакта:
        * экипировать его в свободный слот;
        * отметить объект как подобранный (убрать из списка объектов комнаты);
        * вернуть текстовый результат (что было подобрано);
    - если все слоты заняты, действие недоступно (сообщение "нет свободных слотов");
    - если артефакт уже подобран, действие недоступно.

7. Проверка эффекта артефакта:
    - расширить определение комнаты полем `опасность` (тип опасности,
      например, `fire`);
    - при попытке перехода в комнату с опасностью:
        * если у игрока экипирован артефакт с соответствующей защитой,
          переход разрешён;
        * иначе переход запрещён с сообщением о причине.

8. Инициализация состояния игрока:
    - при старте игры слоты экипировки пусты.

9. Обновить тестовые данные:
    - в одной из комнат должен быть артефакт `ring_of_quiet_flame`;
    - в другой комнате должна быть опасность `fire` (огненная завеса);
    - артефакт должен иметь описание для осмотра.

10. Юнит-тесты в `domain` для:
    - загрузки артефакта;
    - подбора артефакта в слот экипировки;
    - проверки, что артефакт экипирован;
    - недоступности подбора при заполненных слотах;
    - недоступности подбора уже подобранного артефакта;
    - защиты от опасности при экипированном артефакте;
    - запрета перехода при отсутствии защиты.

Не входит в задачу:

- Другие артефакты (только `ring_of_quiet_flame` для проверки архитектуры).
- Визуальные эффекты артефакта (иконки, спрайты).
- Снятие артефакта со слота (на данном этапе артефакты постоянны).
- Обмен артефактов между слотами.
- Существа, mastery marks.
- Сохранение и загрузка состояния.

## Module Placement

- Модель артефакта → модуль `domain`, пакет `tower.domain.data` или `tower.domain.artifact`.
- Расширение состояния игрока → модуль `domain`, пакет `tower.domain.state`.
- Расширение резолвера и экзекутора → модуль `domain`, пакет `tower.domain.logic`.
- Загрузка артефактов → модуль `engine`, пакет `tower.engine.data`.
- Тестовые JSON-файлы → `assets/data/artifacts/`.

Перед началом изучи фактическую структуру кода после предыдущих задач.
Не предполагай имена существующих классов.
Расширяй существующую модель, а не создавай параллельную.

## Constraints

- Не добавлять новые внешние зависимости.
- У `domain` по-прежнему ноль runtime-зависимостей.
- DTO-классы должны оставаться совместимыми с существующим парсером в `engine`.
- Артефакт работает через существующую модель действий,
  не требует отдельной системы.
- Количество слотов экипировки фиксировано (например, 3).
- Подбор артефакта — действие на объекте.
- Эффект артефакта применяется автоматически, не требует отдельного действия.
- Подобранный артефакт исчезает из списка объектов комнаты.
- Если все слоты заняты, подбор недоступен.
- Не менять `desktop`.

## Acceptance Criteria

1. В `assets/data/artifacts/` существует JSON-файл с описанием артефакта
   `ring_of_quiet_flame`.
2. Артефакт загружается при старте игры.
3. В одной из тестовых комнат есть артефакт как объект.
4. При выборе артефакта в списке действий появляется `Подобрать`.
5. Подбор артефакта экипирует его в слот.
6. Артефакт исчезает из списка объектов комнаты.
7. Отображается сообщение о подборе.
8. В другой комнате есть опасность `fire`.
9. Без артефакта переход в комнату с опасностью запрещён.
10. С экипированным артефактом переход разрешён.
11. Юнит-тесты для всех сценариев существуют и проходят.
12. `./gradlew build` завершается успешно.
13. `./gradlew domain:test` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew domain:test
./gradlew desktop:run
```

При запуске:

- в одной комнате виден артефакт;
- можно подобрать артефакт;
- артефакт исчезает из списка;
- попытка перехода в комнату с огненной завесой без артефакта запрещена;
- с экипированным артефактом переход разрешён.

Проверка, что модуль `desktop` не менялся:

```bash
git diff --name-only desktop/
```

Команда должна вернуть пустой результат.
