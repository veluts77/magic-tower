# TASK-018 — Debug Feature: Start in Specified Room

## Goal

Добавить возможность запускать игру в произвольной указанной комнате
через аргумент командной строки. Это инструмент для отладки и настройки
раскладки объектов в комнатах.

## Design Context

После введения явного позиционирования объектов (TASK-017) возникла
необходимость быстро проверять раскладку в конкретных комнатах,
не проходя игру с самого начала.

Запуск в произвольной комнате позволяет:

- проверить координаты объектов в конкретной комнате;
- убедиться, что спрайты стоят на своих местах;
- тестировать переходы между комнатами;
- настраивать раскладку без прохождения всей игры.

Это отладочная функция. Она не влияет на обычный игровой процесс:
при запуске без аргументов игра стартует в стандартной стартовой комнате.

## Механизм запуска

Используется аргумент командной строки:

```
--room=<room_id>
```

Примеры:

```bash
./gradlew desktop:run --args="--room=map_hall"
./gradlew desktop:run --args="--room=gatekeeper_cell"
./gradlew desktop:run --args="--room=hidden_cell"
```

При запуске без аргумента `--room` игра стартует в стандартной комнате:

```bash
./gradlew desktop:run
```

## Поведение

### При указании корректного `room_id`

- Игра загружает данные этажа как обычно.
- Текущая комната устанавливается в указанную.
- Игрок оказывается в указанной комнате.
- Состояние игрока остаётся стандартным для начала игры
  (стандартные заклинания, духи, артефакты).

### При указании некорректного `room_id`

- В лог выводится предупреждение с указанием, что комната не найдена.
- Игра стартует в стандартной стартовой комнате.
- Игра не падает.

### При отсутствии аргумента `--room`

- Игра стартует в стандартной стартовой комнате.
- Поведение идентично текущему.

## Scope

Входит в задачу:

1. Добавить парсинг аргументов командной строки в модуле `desktop`.
   - Распознать аргумент `--room=<room_id>`.
   - Извлечь значение `room_id`.
   - Передать его в модуль `engine`.

2. Добавить передачу `room_id` из `desktop` в `engine`.
   - Это может быть параметр конструктора игры, конфигурационный объект
     или другой механизм передачи данных при инициализации.
   - Способ передачи выбирает агент, исходя из текущей архитектуры.

3. Добавить инициализацию игры в указанной комнате в модуле `engine`.
   - При наличии `room_id` установить текущую комнату в указанную.
   - При отсутствии или некорректности `room_id` использовать стандартную.

4. Обработать некорректный `room_id`.
   - Вывести предупреждение в лог.
   - Использовать стандартную стартовую комнату.
   - Не падать.

5. Сохранить существующее поведение при запуске без аргументов.

Не входит в задачу:

- Изменение механик игры.
- Изменение системы действий, печатей, заклинаний.
- Изменение данных комнат.
- Изменение раскладки объектов.
- Изменение нижней панели.
- Изменение разрешения окна.
- Добавление других аргументов командной строки.
- Графический интерфейс для выбора комнаты.

## Module Placement

- Парсинг аргументов → модуль `desktop`, класс `DesktopLauncher`.
- Передача данных в игру → модуль `engine`, класс игры или конфигурация.
- Инициализация в комнате → модуль `engine`, класс игры или экран.
- Модуль `domain` не изменяется, если для установки текущей комнаты
  достаточно существующих механизмов.

Перед началом изучи фактическую структуру кода после предыдущих задач.
Не предполагай имена существующих классов.

## Constraints

- Не добавлять новые внешние зависимости.
- Не изменять модуль `domain`, если это не необходимо.
- Не изменять данные комнат.
- Не изменять механики игры.
- Аргумент командной строки: `--room=<room_id>`.
- При некорректном `room_id` — предупреждение в лог и стандартный старт.
- При отсутствии аргумента — стандартный старт.
- Игра не должна падать при любых входных данных.

## Acceptance Criteria

1. При запуске с `--room=<room_id>` игра стартует в указанной комнате.
2. При запуске без аргументов игра стартует в стандартной комнате.
3. При указании некорректного `room_id` выводится предупреждение в лог
   и игра стартует в стандартной комнате.
4. Игра не падает при любых входных данных.
5. Состояние игрока остаётся стандартным при запуске в произвольной комнате.
6. Переходы между комнатами работают.
7. Действия с объектами работают.
8. `./gradlew build` завершается успешно.
9. `./gradlew domain:test` завершается успешно.
