# TASK-013 — MVP Floor: Full Playable Tower Floor

## Goal

Собрать первый полноценный игровой этаж, использующий все ранее
реализованные механики: навигацию, объекты, заклинания, духов,
артефакты, существа и систему печатей понимания.

Эта задача не вводит новые механики. Это контентная задача —
создание осмысленного этажа, который можно пройти от начала до конца.

## Design Context

В предыдущих задачах мы реализовали все строительные блоки игры:

- TASK-006: навигация между комнатами;
- TASK-007: взаимодействие с объектами;
- TASK-008: заклинания;
- TASK-009: духи;
- TASK-010: артефакты;
- TASK-011: существа;
- TASK-012: печати понимания и прогрессия этажа.

Теперь нужно соединить их в единый игровой опыт.

Этаж называется **"Пыльный архив"** (Dusty Archive).

Игрок начинает в прихожей архива и должен исследовать этаж,
используя все доступные механики, чтобы собрать 7 из 8 печатей
и подняться на следующий этаж.

## Scope

Входит в задачу:

### 1. Создание 5 комнат

1. **Прихожая архива** (entrance_hall) — стартовая комната.
    - Объекты: сломанная люстра, засыпанный пол, закрытая дверь вглубь.
    - Переход: в Зал карт.

2. **Зал карт** (map_hall) — комната с первым заклинанием.
    - Объекты: стол с картами, магический фонарь, запечатанный ящик.
    - На столе — страница заклинания `push` (толчок).
    - Фонарь не горит, но на нём можно использовать `spark`.
    - Переходы: в Прихожую и в Затопленную галерею.

3. **Затопленная галерея** (flooded_gallery) — комната с артефактом.
    - Особенность: часть пола покрыта магической пылью, создающей опасность `fire`.
    - Объекты: кольцо тихого пламени (артефакт), древний фолиант.
    - Переходы: в Зал карт и в Келью привратника (но через опасность `fire`).

4. **Келья привратника** (gatekeeper_cell) — комната с существом.
    - Объекты: пепельный слизень (существо), старый сундук (заблокирован существом).
    - Слизень нейтрализуется заклинанием `spark`.
    - После нейтрализации сундук доступен, в нём — ключ от скрытой кельи.
    - Переходы: обратно в Затопленную галерею и в Скрытую келью (требует ключа).

5. **Скрытая келья** (hidden_cell) — финальная комната этажа.
    - Объекты: древний алтарь, лестница наверх.
    - На алтаре — страница заклинания `seeker` (призыв духа-искателя).
    - Лестница — переход на следующий этаж, доступен только при 7+ печатях.
    - В этой комнате есть скрытый объект `древняя_руна`, видимый только
      после призыва духа `seeker`.

### 2. Три заклинания

- `spark` (Искра) — даётся игроку при старте. Применяется к объектам и существам.
- `push` (Толчок) — находится на столе в Зале карт. Может применяться к объектам.
- `seeker` (Искатель) — находится в Скрытой келье. Это заклинание призыва духа.

### 3. Один дух

- `seeker` (Дух-искатель) — призывается заклинанием `seeker`.
  После призыва в комнате расскрывает скрытые объекты.

### 4. Один артефакт

- `ring_of_quiet_flame` (Кольцо тихого пламени) — в Затопленной галерее.
  Защищает от опасности `fire`, позволяя пройти через Затопленную галерею
  в Келью привратника.

### 5. Одно существо

- `ash_slug` (Пепельный слизень) — в Кельи привратника.
  Блокирует доступ к сундуку. Нейтрализуется заклинанием `spark`.

### 6. Восемь печатей понимания

1. `found_spark` — найти заклинание `spark` (автоматически, даётся при старте).
2. `found_push` — найти заклинание `push` в Зале карт.
3. `lit_the_lantern` — применить `spark` к магическому фонарю в Зале карт.
4. `picked_ring` — подобрать артефакт `ring_of_quiet_flame`.
5. `entered_gatekeeper_cell` — войти в Келью привратника (требует артефакт).
6. `neutralized_slug` — нейтрализовать `ash_slug` заклинанием `spark`.
7. `summoned_seeker` — призвать духа `seeker` в Скрытой келье.
8. `found_hidden_rune` — найти скрытую руну после призыва духа.

Для перехода на следующий этаж нужно собрать **7 из 8**.

### 7. Переход на следующий этаж

- В Скрытой келье есть лестница — переход на второй этаж.
- Переход доступен только при 7+ собранных печатях.
- Для этой задачи второй этаж может быть минимальным: одна пустая комната
  с сообщением "Этот этаж будет добавлен позже".

### 8. Логическая последовательность

Типичный путь прохождения:

1. Прихожая → Зал карт.
2. Взять заклинание `push` со стола.
3. Применить `spark` к фонарю (получить печать).
4. Вернуться в Прихожую и пойти в Затопленную галерею.
5. Подобрать кольцо (получить печать).
6. С экипированным кольцом пройти в Келью привратника (получить печать).
7. Нейтрализовать слизня искрой (получить печать).
8. Открыть сундук и взять ключ.
9. Вернуться через Затопленную галерею, Зал карт, Прихожую, обратно в Зал карт
   и дальше в Скрытую келью (через ключ).
10. Взять заклинание `seeker`.
11. Призвать духа (получить печать).
12. Найти скрытую руну (получить печать).
13. Подняться выше (при 7+ печатях).

Не входит в задачу:

- Новые механики, типы действий, типы сущностей.
- Новые заклинания, духи, артефакты, существа сверх перечисленных.
- Полноценный второй этаж.
- Реальные спрайты, визуальные эффекты, анимации.
- Сохранение и загрузка прогресса между запусками.
- Изменение UI (команды, экран).
- Изменение архитектуры модулей.

## Module Placement

- Основные изменения — в `engine` (загрузка данных, отображение прогресса).
- Новые JSON-файлы в `assets/data/`:
    - `floors/floor_01_dusty_archive.json`
    - `spells/spark.json`, `spells/push.json`, `spells/seeker.json`
    - `spirits/seeker.json`
    - `artifacts/ring_of_quiet_flame.json`
    - `creatures/ash_slug.json`
- Старые тестовые данные (из TASK-003, TASK-008 и т.д.) можно удалить
  или заменить на новые, если они больше не нужны.
- Модуль `domain` должен измениться минимально:
  только если нужно расширить загрузчик данных или логику,
  чтобы поддержать новые комбинации механик.
- Модуль `desktop` не меняется.

Перед началом изучи фактическую структуру кода после предыдущих задач.
Убедись, что все существующие механики работают как ожидается.
Если для поддержки новой структуры данных нужны минимальные изменения
в `domain` — делай их, но не перестраивай архитектуру.

## Constraints

- Не добавлять новые механики. Использовать только то, что уже реализовано.
- Не добавлять новые внешние зависимости.
- Не создавать файлы изображений. Вся графика — программные заглушки.
- Не менять существующие интерфейсы домена без необходимости.
- Не усложнять UI.
- Весь контент этажа — в JSON-файлах, не в коде.
- Игрок начинает с одним известным заклинанием (`spark`) и без артефактов.
- Все существа пассивные.
- Не менять `desktop`.

## Acceptance Criteria

1. В `assets/data/` существует полная структура данных для этажа.
2. При запуске приложения загружается этаж "Пыльный архив".
3. Игрок начинает в прихожей с одним заклинанием `spark`.
4. Можно исследовать все 5 комнат, используя существующую навигацию.
5. Можно найти и взять заклинания `push` и `seeker`.
6. Можно подобрать артефакт `ring_of_quiet_flame`.
7. С артефактом можно пройти через опасность `fire`.
8. Можно нейтрализовать существо `ash_slug` заклинанием `spark`.
9. Можно призвать духа `seeker` заклинанием `seeker`.
10. После призыва духа расскрываются скрытые объекты.
11. Отображается прогресс печатей (например, "Печати: 5/8").
12. При получении новой печати отображается сообщение.
13. При 7+ печатях доступно действие "подняться выше".
14. Переход на второй этаж работает, отображается минимальное сообщение.
15. `./gradlew build` завершается успешно.
16. `./gradlew domain:test` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew domain:test
./gradlew desktop:run
```

При запуске:

- виден прогресс печатей;
- можно пройти весь этаж от прихожей до скрытой кельи;
- все механики работают вместе;
- при 7+ печатях можно подняться на второй этаж.

Рекомендуется также прогнать ручное прохождение по описанному пути
(см. секцию "Логическая последовательность") и убедиться,
что все печати выдаются корректно.
