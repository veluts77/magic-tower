# TASK-017 — Object Positioning: Explicit Coordinates and Layout

## Goal

Заменить автоматическую раскладку объектов в комнате на явное позиционирование
по координатам. Каждый объект получает позицию, размер, z-порядок и тип
(интерактивный или декоративный). Надписи к объектам убираются.

Это ключевой шаг для визуальной целостности комнат: объекты будут расположены
в соответствии с фоном, а не в автоматической сетке.

## Design Context

В текущей реализации объекты в комнате расставляются автоматически.
Это приводит к проблемам:

- Объекты меняют положение при изменении их количества.
- Объекты не соответствуют композиции фона.
- Нет контроля над порядком отрисовки (что поверх чего).
- Надписи к объектам избыточны после вставки спрайтов.

Цель этой задачи:

- Каждый объект в комнате имеет явную позицию, размер и z-порядок.
- Объекты делятся на интерактивные и декоративные.
- Двери и объекты на стенах имеют поле «стена» для будущих механик.
- Автоматическая раскладка убирается.
- Надписи к объектам убираются.

## Координатная система

Используются относительные координаты в диапазоне от 0.0 до 1.0:

- (0.0, 0.0) — верхний левый угол области комнаты.
- (1.0, 1.0) — нижний правый угол области комнаты.
- x — горизонтальная позиция (0 = слева, 1 = справа).
- y — вертикальная позиция (0 = сверху, 1 = снизу).

Размеры объектов тоже относительные:

- width: 0.1 означает 10% ширины области комнаты.
- height: 0.15 означает 15% высоты области комнаты.

При отрисовке движок умножает относительные значения на реальные
размеры области комнаты. Например, при области 1280×600:

- позиция (0.5, 0.5) → пиксели (640, 300);
- размер (0.1, 0.15) → пиксели (128, 90).

## Формат описания объекта

Каждый объект в данных комнаты должен иметь следующие поля:

```
объект:
  id: строка                    — идентификатор объекта
  тип: "interactive" | "decorative"
  спрайт: строка               — идентификатор спрайта
  позиция: { x: число, y: число }
  размер: { width: число, height: число }
  z: целое число               — порядок отрисовки, больше = выше
  стена: "back" | "left" | "right" | "floor" | null
  переход: строка | null       — идентификатор комнаты (для дверей)
```

Поле «стена» — метаданные для будущих механик (например, клик по двери).
На данном этапе не влияет на отрисовку, позиция задаётся координатами.

## Типы объектов

- **interactive** — объект можно выбрать, осмотреть, применить заклинание.
  Участвует в системе действий.
- **decorative** — объект только отображается. Не участвует в выборе действий.

## Scope

Входит в задачу:

1. Расширить определение объекта в модуле `domain`:
    - добавить поля: позиция, размер, z-порядок, тип, стена;
    - эти поля являются частью данных комнаты, не логикой рендеринга.

2. Расширить загрузчик данных в модуле `engine`:
    - читать новые поля из JSON;
    - передавать их в состояние комнаты.

3. Изменить отрисовку комнаты в модуле `engine`:
    - рисовать объекты по явным координатам и размерам;
    - учитывать z-порядок при отрисовке;
    - убрать автоматическую раскладку;
    - убрать надписи к объектам.

4. Изменить выбор объектов в модуле `engine`:
    - выбор объекта происходит по его координатам и размеру;
    - декоративные объекты не участвуют в выборе;
    - интерактивные объекты можно выбрать как раньше.

5. Обновить данные комнат в JSON:
    - добавить координаты, размеры, z-порядок, тип для каждого объекта;
    - использовать значения из таблиц, предоставленных пользователем.

6. Сохранить существующую функциональность:
    - действия с объектами работают как раньше;
    - переходы между комнатами работают;
    - прогресс печатей работает;
    - нижняя панель работает.

Не входит в задачу:

- Изменение механик игры.
- Изменение системы действий.
- Изменение системы печатей.
- Изменение модуля `desktop`.
- Изменение разрешения окна или нижней панели.
- Анимация.
- Звук.

## Module Placement

- Расширение определения объекта → модуль `domain`, пакет `tower.domain.data`.
- Расширение загрузчика данных → модуль `engine`, пакет `tower.engine.data`.
- Изменение отрисовки комнаты → модуль `engine`, пакет `tower.engine.render`.
- Изменение выбора объектов → модуль `engine`, пакет `tower.engine.input` или `tower.engine.screen`.
- Обновление данных комнат → файлы в `assets/data/floors/`.

Перед началом изучи фактическую структуру кода после предыдущих задач.
Не предполагай имена существующих классов.

## Constraints

- Не добавлять новые внешние зависимости.
- Не изменять модуль `desktop`.
- Не изменять систему действий, печатей, заклинаний, духов, артефактов, существ.
- Не изменять нижнюю панель.
- Не изменять разрешение окна.
- Координаты относительные (0.0–1.0).
- Размеры относительные (0.0–1.0).
- Декоративные объекты не участвуют в выборе действий.
- Надписи к объектам убрать.
- Автоматическую раскладку убрать.
- Использовать координаты из таблиц выше без изменений.
- Поле «стена» — метаданные, не влияет на отрисовку на данном этапе.

## Acceptance Criteria

1. Каждый объект в комнате имеет явную позицию, размер, z-порядок и тип.
2. Объекты отрисовываются по явным координатам.
3. Автоматическая раскладка убрана.
4. Надписи к объектам убраны.
5. Декоративные объекты отображаются, но не участвуют в выборе действий.
6. Интерактивные объекты можно выбрать и выполнять с ними действия.
7. Объекты отрисовываются в правильном порядке (z-порядок).
8. Переходы между комнатами работают.
9. Действия с объектами работают как раньше.
10. Прогресс печатей работает.
11. Нижняя панель работает.
12. Модуль `desktop` не изменён.
13. `./gradlew build` завершается успешно.
14. `./gradlew domain:test` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew domain:test
./gradlew desktop:run
```

При запуске:

- объекты в комнатах расположены в соответствии с координатами;
- надписи к объектам отсутствуют;
- декоративные объекты видны, но не выбираются;
- интерактивные объекты выбираются и работают;
- переходы между комнатами работают;
- нижняя панель работает.

Проверка, что модуль `desktop` не менялся:

```bash
git diff --name-only desktop/
```

Команда должна вернуть пустой результат.

Если GUI недоступен, достаточно успешной сборки и тестов,
а в отчёте указать: `GUI not tested`.
