# TASK-004 — Screen Abstraction and Room View with Placeholders

## Goal

Создать экранную абстракцию и первый игровой экран,
который отображает загруженную комнату из данных, полученных в TASK-003.
Отображение выполняется программными заглушками (цветные фигуры, текст),
без использования файлов изображений.

## Design Context

В libGDX для управления экранами используется интерфейс `Screen`
и класс `Game`, который позволяет переключать экраны через `setScreen()`.

Нам нужен игровой экран, который:
- получает данные о текущей комнате;
- отображает комнату и её объекты;
- в будущем будет обрабатывать ввод и показывать действия.

На данном этапе мы делаем только отображение.
Никакой игровой логики, действий или взаимодействия с объектами.

Все визуальные элементы — программные заглушки:
- фон комнаты — однотонный прямоугольник;
- объекты — цветные фигуры с текстовой подписью;
- персонаж — маленький цветной маркер;
- название комнаты — текст в верхней части экрана.

Это позволяет разрабатывать механику, не ожидая готовности арта.

## Scope

Входит в задачу:

1. Создать игровой экран, реализующий интерфейс `Screen` из libGDX.
   Экран должен отображать текущую комнату.

2. Реализовать отрисовку комнаты программными средствами:
    - фон комнаты: однотонный прямоугольник, занимающий основную часть экрана;
    - название комнаты: текст в верхней части экрана;
    - объекты комнаты: цветные прямоугольники или круги с текстовой подписью;
    - маркер персонажа: маленькая цветная фигура в фиксированной позиции.

3. Расположение объектов на экране определяется автоматически.
   На данном этапе не нужно загружать координаты из данных.
   Достаточно распределить объекты по сетке или в ряд
   в пределах области комнаты.

4. Подключить игровой экран к главному классу игры.
   При запуске приложения должен отображаться игровой экран
   с данными тестового этажа, загруженного в TASK-003.
   Используется первая комната из загруженного этажа.

5. При нажатии ESC приложение закрывается.

6. Отобразить отладочную информацию в углу экрана:
    - идентификатор текущей комнаты;
    - количество объектов в комнате.

Не входит в задачу:

- Обработка кликов по объектам.
- Система действий или команд.
- Переключение между комнатами.
- Переключение между экранами (меню, настройки и т.д.).
- Загрузка или отображение спрайтов из файлов.
- Анимация.
- Звук.
- Игровая логика (прогрессия, заклинания, духи).
- Сохранение состояния.

## Module Placement

- Игровой экран → модуль `engine`, пакет `tower.engine.screen`.
- Отрисовка комнаты → модуль `engine`, пакет `tower.engine.render`.
- Главный класс игры обновляется для подключения экрана → модуль `engine`.
- Модуль `domain` не изменяется.
- Модуль `desktop` не изменяется.

## Constraints

- Не добавлять новые внешние зависимости.
- Не создавать файлы изображений.
  Вся графика рисуется программно.
- Для рисования фигур использовать `ShapeRenderer` из libGDX.
- Для рисования текста использовать `BitmapFont` из libGDX.
  Допустимо использовать стандартный шрифт,
  встроенный в libGDX (созданный через `new BitmapFont()`).
- Не создавать сложные абстракции для управления экранами.
  Достаточно использовать встроенный механизм `Game.setScreen()`.
- Не создавать отдельный класс для камеры на данном этапе.
  Можно использовать `OrthographicCamera` напрямую в экране,
  если это необходимо, но без дополнительных обёрток.
- Цвета заглушек могут быть любыми, но должны различаться:
  фон, объекты и маркер персонажа должны быть визуально отличимы.
- Экран должен корректно освобождать ресурсы в методе `dispose()`.

## Acceptance Criteria

1. При запуске приложения открывается окно с игровым экраном.
2. В верхней части экрана отображается название комнаты.
3. В области комнаты отображаются цветные фигуры,
   представляющие объекты комнаты.
4. Рядом с каждой фигурой отображается текстовая подпись
   с именем объекта.
5. В области комнаты отображается маркер персонажа.
6. В углу экрана отображается отладочная информация:
   идентификатор комнаты и количество объектов.
7. Данные для отображения берутся из загрузчика,
   реализованного в TASK-003.
8. ESC закрывает приложение.
9. В модуле `domain` нет новых изменений.
10. `./gradlew build` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew desktop:run
```

При запуске должно открыться окно, в котором отображается:
- название комнаты;
- несколько цветных фигур с подписями;
- маркер персонажа;
- отладочная информация.

```bash
git diff --name-only domain/
```
