# TASK-009 — Spirits and Spirit Summoning

## Goal

Добавить в игру систему духов — магических сущностей, которых можно призвать
для помощи в исследовании башни.

Духи работают как особые действия: игрок может призвать духа,
и тот выполняет определённую функцию (например, ищет скрытые предметы).

## Design Context

В TASK-008 мы реализовали заклинания, которые применяются к объектам.
Духи — это следующая магическая система, но с особенностями:

- Духи не применяются к конкретным объектам.
- Дух призывается в текущей комнате.
- После призыва дух выполняет свою функцию (ищет, открывает, защищает).
- Результат действия духа зависит от контекста комнаты.

Пример:
- Игрок входит в комнату.
- В списке действий для комнаты (не для объекта) появляется `Призвать: Искатель`.
- Игрок призывает духа.
- Дух ищет скрытые предметы в комнате.
- Если скрытый предмет найден, он становится доступен для взаимодействия.
- Отображается сообщение о результате.

Это демонстрирует, что система действий поддерживает разные типы действий:
- действия на комнате (осмотреться, перейти, призвать духа);
- действия на объектах (осмотреть, применить заклинание);
- будущие действия (использовать артефакт, взаимодействовать с существом).

## Scope

Входит в задачу:

1. Модель духа в `domain`:
    - идентификатор (строка);
    - отображаемое имя;
    - описание;
    - тип функции (что делает дух: ищет, открывает, защищает).
      На данном этапе реализуем только функцию `ищет` (seeker).

2. Состояние игрока в `domain`:
    - список идентификаторов известных духов;
    - метод добавления духа;
    - метод проверки, знает ли игрок духа.

3. Загрузка духов из JSON:
    - создать структуру `assets/data/spirits/`;
    - создать тестовый JSON с описанием одного духа `seeker` (искатель);
    - расширить `DataLoader` для загрузки духов.

4. Расширение определения комнаты в `domain`:
    - добавить поле `скрытые объекты` (список идентификаторов объектов,
      которые скрыты до призыва духа);
    - или использовать флаги комнаты для отметки скрытых объектов.

5. Состояние комнаты в `domain`:
    - добавить поле для отслеживания, был ли призван дух в этой комнате;
    - добавить поле для списка найденных (расскрытых) объектов.

6. Расширение резолвера действий в `domain`:
    - при получении действий для комнаты, если у игрока есть известный дух
      и дух ещё не был призван в этой комнате, добавить действие `призвать духа`;
    - действие должно иметь тип `призвать духа` и цель `идентификатор духа`.

7. Расширение экзекутора действий в `domain`:
    - поддержать действие `призвать духа`;
    - при призыве духа `seeker` в комнате:
        * отметить, что дух был призван;
        * найти все скрытые объекты в комнате;
        * расскрыть их (добавить в список доступных объектов);
        * вернуть текстовый результат (что было найдено);
    - если дух уже был призван в этой комнате, действие недоступно;
    - если игрок не знает духа, действие не появляется.

8. Инициализация состояния игрока:
    - при старте игры игрок знает одного духа `seeker`;
    - это можно сделать через код (не через сохранение).

9. Расширение игрового экрана в `engine`:
    - при отображении списка действий для комнаты показывать
      действие призыва духа, если оно доступно;
    - после призыва духа обновить список объектов в комнате
      (показать расскрытые объекты).

10. Обновить тестовые данные:
    - в тестовой комнате должен быть хотя бы один скрытый объект;
    - скрытый объект должен иметь описание для осмотра;
    - скрытый объект не должен отображаться до призыва духа.

11. Юнит-тесты в `domain` для:
    - загрузки духа;
    - добавления духа в состояние игрока;
    - проверки, что игрок знает духа;
    - получения действий для комнаты с возможностью призыва;
    - призыва духа в комнате;
    - расскрытия скрытых объектов после призыва;
    - недоступности призыва, если дух уже призван;
    - недоступности призыва, если игрок не знает духа.

Не входит в задачу:

- Другие духи (только `seeker` для проверки архитектуры).
- Духи, привязанные к конкретным этажам (это будущая механика).
- Визуальные эффекты призыва (анимация, спрайты).
- Артефакты, существа.
- Mastery marks и прогрессия этажа.
- Сохранение и загрузка состояния.
- Сложные взаимодействия между духами.

## Module Placement

- Модель духа → модуль `domain`, пакет `tower.domain.data` или `tower.domain.spirit`.
- Расширение состояния игрока → модуль `domain`, пакет `tower.domain.state`.
- Расширение состояния комнаты → модуль `domain`, пакет `tower.domain.state`.
- Расширение резолвера и экзекутора → модуль `domain`, пакет `tower.domain.logic`.
- Загрузка духов → модуль `engine`, пакет `tower.engine.data`.
- Тестовые JSON-файлы → `assets/data/spirits/`.
- Обновление игрового экрана → модуль `engine`, пакет `tower.engine.screen`.

Не предполагай имена существующих классов.
Расширяй существующую модель, а не создавай параллельную.

## Constraints

- Не добавлять новые внешние зависимости.
- У `domain` по-прежнему ноль runtime-зависимостей.
- DTO-классы должны оставаться совместимыми с существующим парсером в `engine`.
- Дух работает через существующую модель действий,
  не требует отдельной системы.
- Не создавать систему маны, кулдаунов или стоимости призыва.
- Дух можно призвать только один раз в комнате.
- После призыва скрытые объекты становятся доступными для взаимодействия.
- Скрытые объекты не отображаются в списке объектов до призыва духа.
- Не менять `desktop`.

## Acceptance Criteria

1. В `assets/data/spirits/` существует JSON-файл с описанием духа `seeker`.
2. Дух загружается при старте игры.
3. Игрок при старте знает духа `seeker`.
4. В тестовой комнате есть скрытый объект.
5. Скрытый объект не отображается в списке объектов до призыва духа.
6. В списке действий для комнаты появляется `Призвать: Искатель`.
7. Призыв духа расскрывает скрытые объекты.
8. После призыва скрытые объекты появляются в списке объектов.
9. Отображается сообщение о результате призыва.
10. Повторный призыв духа в той же комнате недоступен.
11. Если игрок не знает духа, действие призыва не появляется.
12. Юнит-тесты для всех сценариев существуют и проходят.
13. `./gradlew build` завершается успешно.
14. `./gradlew domain:test` завершается успешно.

## Verification

```bash
./gradlew build
./gradlew domain:test
./gradlew desktop:run
```

При запуске:

- видна комната с обычными объектами;
- скрытые объекты не видны;
- в списке действий для комнаты есть `Призвать: Искатель`;
- призыв духа отображает сообщение о найденных объектах;
- скрытые объекты появляются в списке;
- можно взаимодействовать с расскрытыми объектами;
- повторный призыв недоступен.

Проверка, что модуль `desktop` не менялся:

```bash
git diff --name-only desktop/
```

Команда должна вернуть пустой результат.
